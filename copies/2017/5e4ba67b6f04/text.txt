Enforce HTTPS for distribution of software as a security measure against targeted malware attacks
https://github.com/videolabs/mirrorbits/issues/59
opened 2017-06-30T15:13:46Z by fpietrosanti · state closed

Following Snowden NSA and Wikileaks CIA releases the internet community has been shaked in the understanding of how massive surveillance and targeted attacks works.

The basic attacks to infect computer with software malware is to intercept "on the wire" the package download, infect it "on-the-fly" and let the end-user finish the download and install it.

This major attack can be prevented by having a default HTTPS transport from the download mirror, considering that the additional costs of HTTPS vs HTTP is today negligible.

This ticket is to have mirrorbits to enforce all of the mirror download URLs to be only HTTPS, operating a plan to enforce HTTPS as the only download method, eventually working closely with the download mirrors.

--- 2017-07-04T09:01:02Z fpietrosanti
@etix Nope, that's not how security works. 
To prevent MITM attacks you need "connection security" between the piece of software operating the download (the browser) and the piece of software serving the installation file (the server operating HTTP/S protocol).

If you expect to rely on end-users good practices to verify signatures, that' so '90s expectations of crypto communities, that failed. 
Today security paradigm require automation and protection of each step, so first protect the transport against MITM (full HTTPS path with HSTS between each browser interaction), then as a good practice (that unfortunately have no practical uses by almost all users) also deploy signatures and inform end-users on how to verify it.
